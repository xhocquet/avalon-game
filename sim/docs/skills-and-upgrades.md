# Skills & Upgrades

- Four slots per hero — `Primary`, `Secondary`, `Tertiary`, `Ultimate` ([`SkillSlot`](../Enums.cs)) — ranked 0-4. The values index `SkillsComponent`'s fixed buffers and `HeroAsset.Skill1..4AssetId`, so they stay 0-based and contiguous.
- Numbers live in [`SkillAsset`](../Assets/SkillAsset.cs), four rows per hero in the `AssetIds.Skill*` block (500-519), its own rows even where two heroes match. **A skill's whole tuning surface is its row**: nothing about damage, speed, range, radius, count, spacing, duration, or multiplier may be decided in code. `CrystalBulletsTests.EveryProjectileNumber_TracesBackToTheAssetRow` fails if any of it drifts back into a literal.
- `Description` is the row's one non-tuning field: the tooltip blurb, authored beside the numbers it describes rather than in the client's `SkillCatalog` (which still owns display names). Blank on every row today. `SkillBarController.BuildTooltip` renders it and folds it to width; a blank one drops the paragraph.
- The row is one flat shape for every skill; unused fields sit at 0. Per-rank values are an `X`/`XPerRank` pair resolved with `XAtRank`. `CooldownMs` converts once, at cast time, through `SkillActions.CooldownTicks`.
- State is [`SkillsComponent`](../Components/Behaviors/SkillsComponent.cs) — unspent points, the four asset ids, ranks, cooldowns, all `fixed int` (52B). `HeroFactory` copies the ids off `HeroAsset` at spawn, so the cast path never reaches the asset registry.
- A hero spawns with 1 point and `ExperienceSystem` grants one per level, so points equal level. Points are not a stat; the tree spends them itself.
- Spending and casting both go through [`SkillActions`](../Heroes/SkillActions.cs), dispatched from `CommandSystem`. `CommandValidation.AcceptSkillSlot` is the only thing between a wire value and an unchecked fixed-buffer index. A cast starts its cooldown *before* running the effect, so an effect that kills or respawns its own caster cannot leave the slot free.
- **Mana cost**: `SkillAsset.ManaCost` (+`PerRank`), checked in `EvaluateCast` against the caster's [`Health.Mana`](../Components/Behaviors/Health.cs) pool and spent through [`ManaApplication`](../ManaApplication.cs) right after the cooldown starts, so a rejected cast never pays. `SkillActions.CanCast` folds the check in, so the client greys a slot it cannot afford. 0 (the default on every row today) is a free cast.
- **Targeting**: `CastSkillCommand` carries the planar `TargetX`/`TargetZ` pair `MoveCommand` uses; `SkillActions` hands the effect a [`SkillCastContext`](../Heroes/IHeroSkillSet.cs) — caster, player, slot, asset, rank, caster position, target. Add to that struct, not to `OnCast`'s parameter list. The client aims from `CameraController.ScreenToGround` and deliberately does not snap to the navmesh the way a move order does.
- [`SkillAim.ClampToCastRange`](../Heroes/SkillAim.cs) pulls the aim point onto the `MinCastRange`/`MaxCastRange` band before any effect sees it; 0 on either end is unbounded there. An out-of-band aim is **clamped along the line the client aimed, not rejected**, so a modified client casting across the map lands at its own edge. `CommandValidation` keeps only the world-envelope check. `SkillAim.Direction` falls back to the caster's `Rotation` when the aim point sits on the caster.
- `SelfCast` (0/1) replaces the aim point with the caster's position rather than clamping, so cast, `SkillCastEvent`, and telegraph resolve on the hero whatever a modified client sent. The client reads the same flag through `SkillAsset.IsSelfCast` and fires on key-down instead of entering the hold-to-aim path.
- Hero code is an [`IHeroSkillSet`](../Heroes/IHeroSkillSet.cs) selected by `HeroAsset.SkillSetId` through `HeroSkillSets.Get`, one folder per hero under `Heroes/` owning all four slots, shared plumbing at the root. Everything under `Heroes/` is namespace `...Sim.Heroes` — the folder is not a namespace boundary. Sets are **stateless singletons**, like behaviors. This is separate from `BehaviorId`, which selects spawn/tick logic. An unimplemented slot is an empty `Cast<SkillName>` method; `OnRankGained` is the per-rank hook.
- [`TimedEffectSystem`](../Systems/TimedEffectSystem.cs) owns every per-tick countdown in the frame — attack and skill cooldowns, buff expiry, proc and burst expiry, snare expiry, and charge detonation, the one that pays something out rather than just ending. Registered before `HeroBehaviorSystem` and ahead of `DamageSystem`, so a cooldown reaching 0 is spendable on the same tick. A cast on tick N loses one tick to it on that same tick, because commands are delivered before the Update phase — identical on both peers, so it is not an off-by-one. **A new countdown belongs in that pass, not in a system of its own.**
- `RespawnSystem.ClearActiveState` drops buffs, procs, bursts, snares, and charges on death rather than letting the clocks run out on a corpse.

Eight effect lifecycles are built; every other slot is an empty cast method.

| Lifecycle | Applied through | Row block | Example |
| --- | --- | --- | --- |
| Projectile | [`SkillProjectiles.SpawnVolley`](../Heroes/SkillProjectiles.cs) | `Damage`, `Projectile*` | Crystal Bullets |
| Timed stat buff | [`StatBuffApplication`](../StatBuffApplication.cs) | `BuffDurationMs`, `BuffPercent*` | Harden |
| Empowered attack | [`AttackProcs`](../AttackProcs.cs) | `Proc*` | Spiky Punch |
| Heal | [`HealthApplication.ApplyHeal`](../HealthApplication.cs) | `HealPercent*` | Refresh |
| Attack burst | [`AttackBursts`](../AttackBursts.cs) | `Burst*` | Double Dip |
| Cone | [`SkillCones.ApplyDamage`](../Heroes/SkillCones.cs) | `Damage`, `Cone*` | Venomous Slobber |
| Snare | [`Snares`](../Snares.cs) | `SnareDurationMs*` | Chrysalis |
| Charged burst | [`SkillCharges`](../Heroes/SkillCharges.cs) | `Damage`, `AreaRadius`, `Charge*` | Chrysalis |

- **Projectiles** are one entity per bullet carrying a [`Projectile`](../Components/Units/Projectile.cs), advanced by [`ProjectileSystem`](../Systems/ProjectileSystem.cs) ahead of `DamageSystem` so a projectile kill reaches `DeathSystem` the same tick. A projectile carries no `TeamComponent`/`Health`/`UnitIdComponent` — those are what would make it a target — so the firing team rides on the component as a plain int. Hits are proximity, not physics: the `SpatialHashGrid` broad phase `TargetAcquisitionSystem` uses, then the tick's swept segment against each candidate's `Stats.GameplayRadius`, nearest along the segment with `UnitId` as the tie-break. `CombatTargeting.IsSkillHittable` keeps structures out by default.
- **Cones** resolve on the cast tick and put nothing in the world: `SkillCones.ApplyDamage` walks the units once, damages everything hostile inside the wedge, and is done. `ConeAngleDegrees` is the **full** opening angle and `ConeRange` the reach from the caster's centre, widened by the target's own body; bearing is measured to the target's centre, so a wide body is easier to catch at the far edge than at the sides. Author `MaxCastRange` equal to `ConeRange` - the aim clamp is what the telegraph draws, and a longer band would draw a wedge past what the hit search reaches. Hits are collected before any damage lands, because the first `ApplyDamage` of a match allocates the hit-id singleton and that creates an entity mid-filter.
- **Buffs** store an **absolute expiry tick**, so expiry is one comparison per entry and a rollback replay lands where it did the first time; applied on tick N for D ticks is worth its bonus on N..N+D-1. An entry records **what the stat actually moved by**, not the fraction asked for — `StatRanges` clamps and the stat underneath moves on its own. Entries key on `(source asset id, stat)`, so a recast refreshes instead of compounding; a different source stacks, up to `StatBuffsComponent.MaxEntries`. Which stats one lands on is the skill's business — Harden takes `Armor` and `MagicResist`, one entry each.
- **Procs and bursts** are siblings — one changes what an attack is worth, the other how soon the next comes — and **`DamageSystem` is the only consumer of either**, so a skill or a projectile can never eat a charge the player is holding. Both spend at the point the attack is committed to, past the dead/friendly checks.
  - The proc multiplier is a **total** (4 is 400% of a normal hit) and lands on raw damage **before mitigation**, where `CriticalStrikes` puts its own; the two stack multiplicatively. One slot, not a buffer: re-arming replaces.
  - `AttackBursts.NextCooldownTicks` supplies the swing timer left after each hit. **The spacing can only shorten the wait**, so a slow-authored burst on a fast attacker is never a penalty. `Remaining` counts swings *past* the one the cast bought, so `BurstAttackCount: 2` queues 1. Every swing is a plain attack — the burst never touches damage, and a proc riding along is spent by the first of them.
  - `ProcResetsAttackCooldown`/`BurstResetsAttackCooldown` clear the swing timer at arm/queue time, so the effect opens on the cast tick instead of waiting out the auto before it. The cooldown restarts from that hit, so it buys one swing rather than a faster rate.
- **Snares** take movement away and nothing else - a snared unit still turns, attacks, and casts. The hold is **not** a `MoveSpeed` modifier: it is checked by the movers themselves, `NavigationAgentSystem` and `CommandSystem.Update`, because a stat set to zero would fight every other modifier on it and leak back through a revert that clamped. The nav path parks the agent as `Idle`, which steering, ORCA, and the movement integrator already skip, and leaves `UnitMoveTarget` alone - the order resumes and repaths on its own when the hold ends. One slot per unit, keyed on nothing: overlapping snares keep whichever ends later, so a short one can never cut a long one short.
- **Charged bursts** are the only effect that resolves on a **later tick than the cast that armed it**. The payload - damage, radius, hold - is copied onto `SkillChargeComponent` at cast time rather than re-read at detonation, so a charge always pays what the rank that armed it authored. It is centred on the caster **at detonation**, not at the cast point, which is why Chrysalis roots its own caster for exactly `ChargeDurationMs`. `TimedEffectSystem` fires it, collecting the due charges before detonating any of them; the hit search is [`SkillAreas.Collect`](../Heroes/SkillAreas.cs), the round sibling of `SkillCones`. A caster that dies mid-charge takes the charge with it.
- **An effect that modifies a hit describes itself in its own event, never as a flag on `AttackHitEvent`.** `AttackHitEvent.AttackHitId` (off `AttackHitIdCounter`) is the handle every event about that hit carries; `AttackProcConsumedEvent` names its skill, its multiplier, and the hit it rode in on. One attack spending several effects raises one event each; `Damage` still carries the combined result. `DamageApplication.NextHitId` is public because an effect modifying damage on the way *in* has to raise its event before the hit exists. Ids are allocated **whether or not anything is listening** — the counter is frame state, so a peer with no `EventRaiser` burns the same ids or the frames stop hashing the same.
- Otherwise one event per phase: `SkillCastEvent` (Synced), `SkillProjectileSpawnedEvent`/`SkillProjectileDespawnedEvent` (Regular, matched on `ProjectileId`, one despawn per id born), `SkillChargeDetonatedEvent` (Regular, raised before its hits land), `AttackHitEvent` for damage. Heals raise none.
- Heal percentages are a fraction of the target's `Stats.MaxHealth`, so a heal keeps its meaning as the pool grows with level.
- **Mana restore** is the resource sibling of the heal block: `ManaRestore*` handed to [`ManaApplication.Restore`](../ManaApplication.cs), clamped to the target's `Stats.MaxMana` headroom. The helper is built and ready; no row authors it yet, so a hero that wants it calls `ManaApplication.Restore` from its cast the way `PickleKnightSkills` calls `HealthApplication.ApplyHeal`.
- Damage from any source goes through [`DamageApplication.ApplyDamage`](../DamageApplication.cs) and every upward write through [`HealthApplication`](../HealthApplication.cs), so a skill kill pays XP like an auto-attack does and a heal is never a resurrect.
- A cast is instant: no cast time, no rank prerequisites, no respec. `ManaCost` is the one resource gate; every row authors it 0 today, so casts are free until a designer sets one.
